## 后端整改

1. 新增统一的身份候选兼容性判定。已识别来源必须匹配 Dataset 的公司、报告类型以及当前或上一报告年度；显式冲突、歧义或带企业身份但不相容的候选阻止能力放行、Run 和 Scenario。
2. 人工确认时，匹配来源转为 `identified`；其他已识别企业来源明确保留为 `conflict` 并附加 `identity_mismatch_after_user_confirmation`，不再以另一个 `identified` 来源混入。
3. `evidence_for_snapshot`、研究 `search_documents` 和 Scenario 假设证据校验只接受身份相容来源。没有候选记录的历史快照维持旧兼容读取；一旦存在候选则按身份闭合过滤。
4. `apply_extraction` 先比较当前候选和事实，再在同一事务中发布一个新快照。候选与事实同时变化只增一个版本；只变候选也增版；完全相同的重放不增版；旧版本候选保持不变。
5. 上传测试已更新为真实版本链：来源附加生成版本 2，身份候选发布生成版本 3；重复上传仍复用来源并停留在版本 3。
6. 最终审查发现事实人工复核仍可引用同一 Dataset 中身份不相容来源的证据；现在 `correct_fact` 与 Scenario、研究检索共用相同的身份证据边界，拒绝跨企业 evidence 且不产生新 revision/version。

## 新增回归

- `test_identity_candidate_change_publishes_one_immutable_snapshot`：验证旧版本无候选、候选变化只增一个版本、相同结果重放不增版。
- `test_mixed_company_confirmation_blocks_run_scenario_and_foreign_evidence`：向 EVE Dataset 混入 CATL 来源后确认 CATL，验证 EVE 候选转为冲突、Run/Scenario 返回 `IDENTITY_CONFLICT`、EVE 证据被快照查询和 Scenario 校验拒绝、研究检索只返回 CATL 证据。
- 同一纵向回归还验证 Fact Review 不能把 EVE evidence 挂到 CATL 事实，拒绝时返回 `SCOPE_MISMATCH` 并保持 Dataset 版本不变。

## P1 前端交接与实现

2026-10-15 已按交接要求完成以下本地实现：

1. 在 API client 增加 `listCompanies`、`listIdentityCandidates`、`confirmDatasetIdentity`、`getDatasetCapabilities`，全部复用生成类型并支持请求取消。
2. 工作台支持创建 Dataset 和刷新/选择最新版本；上传后不得只替换 Dataset 后显示空事实。
3. 上传返回后读取身份候选；存在冲突时显示公司、年度、报告类型、证据页和 warning，并阻止 Run/Scenario 入口。
4. 人工确认必须提交 `expected_version`，成功后切换到返回的新版本并重新读取 facts、candidates、capabilities；409 必须提示刷新，不得覆盖当前选择。
5. 展示五模块能力矩阵及原因、缺失输入、证据缺口和可执行动作。
6. 增加上传→冲突提示→人工确认→新版本 Dataset 的组件/API 测试，并覆盖 Dataset 切换时旧响应不得回写。

实现使用 `Dataset ID + version + requestId` 作为前端响应验收身份。facts、身份候选和能力矩阵并行读取但只作为同一快照整体写入；Dataset 切换、同快照刷新和取消后的迟到响应均被丢弃。上传在切换 Dataset 时取消，人工确认与事实刷新还会校验原请求快照；旧版本响应不会覆盖列表中的更高版本。

新增 `DatasetPanel`、`IdentityPanel`、`CapabilityMatrix` 与 `lib/workbench.ts`，并扩展 API client。身份未确认、冲突、歧义或候选与当前 Dataset 不相容时，界面禁用 Run/Scenario；后端门禁仍为最终权威。409 身份版本冲突保留结构化错误并要求用户显式刷新，不自动覆盖当前选择。
