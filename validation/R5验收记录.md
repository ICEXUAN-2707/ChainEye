# R5 后端可追溯报告验收记录

日期：2026-10-05

## 本轮边界

- 启用冻结的 `GET /api/v1/runs/{id}/report?format=json|markdown|pdf`，未新增路由、HTTP DTO、数据库表或前端业务代码。
- 报告仅组装 Run 绑定快照内的 Fact revision、Calculation、Claim、Scenario、AssumptionRecord 和 Evidence；不重新计算财务结果，不让模型生成数字。
- `insufficient` 和 `rejected` Claim 不进入报告正文，并在 `limitations` 披露排除数量；未完成 Run 返回 `409 REPORT_NOT_READY`，不返回空报告。
- 未实现 OCR、通用年报提取、历史价格、预测、登录部署或 R6 能力。

## 实现与原子性

- `ReportService.build(run_snapshot, claims, calculations) -> Report` 对照 Spec 接口实现，并逐项校验 Calculation 输入 Fact revision、Scenario 数据集版本/计算引用、Claim 的 Evidence/Calculation/Assumption 引用和假设集合。
- 完成 Run 只落库一份结构化 Report；JSON 直接返回该记录，Markdown 与 PDF 从同一记录确定性渲染，重复请求保持相同 `generated_at`。
- Report 写入、`report_generated` 事件和 Run 的 `completed/report_ready=true` 在同一 SQLite 事务提交，避免完成态与报告态竞态；并发惰性生成只产生一份报告和一个事件。
- `report` 节点属于可恢复幂等节点；模拟中断后可由单 worker 恢复并完成，仍只产生一个报告事件。

## 仍需实际人员完成

- 关键结论的证据支持性人工逐项签核；程序只证明引用存在、范围合法和数字能在引用对象中精确对照。
- 冻结后未见年报的泛化测试及其失败记录；R2 提取器仍只支持 Spec 已冻结的宁德时代 2024/2025 文本层版式。

- DeepSeek 实际费用仍需供应商账单侧核对；本轮未新增付费模型调用。
