## 本轮边界

- 启用冻结的 Run 创建、读取、事件游标和 `waiting_review` 恢复接口；未增加 HTTP DTO 或路由。
- 编排止于已校验 Claim，`GET /runs/{id}/report` 仍返回 501，未提前实现 R5。
- 只允许 Spec 规定的六个工具；不提供任意代码执行、任意 URL 获取或网络采集。
- DeepSeek 使用固定官方端点，密钥仅从环境读取。Fake 适配器只用于自动化测试，不作为真实模型验收结果。

## PR#7 修复复核

- 活跃Run自动轮询，结束或待复核后停止；事件按`after_seq`增量合并且不重复。
- 数据包或版本变化会中止旧请求并清空旧Run/事件；实时幂等键不再包含隐藏回放ID。
- 恢复条件情景时提交显式假设和确认；事件payload、Claim状态和后端错误码可查看。
- 新增Run纯函数测试并纳入默认前端测试脚本。

## PR#7 二次缺陷修复与漏检倒查

- `counter_evidence_ids` 与普通证据引用统一校验，且允许集合只取实际提供给模型的 Evidence；数据包内存在但模型未见的 ID 也会拒绝。
- `get_facts`、`search_documents`、`compute_financials` 和 `compute_scenario` 的输入已对齐 Spec：显式快照、`top_k<=8`、Fact ID/revision；中文查询按连续双字词检索。
- 缺少已复核基线时当前 Run 以 `FACT_NOT_VERIFIED` 结束并提示在复核后的新快照创建新 Run，不再进入无法修复冻结快照的 `waiting_review`。
- 情景节点增加由确定性 Scenario/Calculation 生成的 Claim，确保情景输出、假设和计算引用进入最终 Claim；模型仍不得自行计算。
- 空 Claim 不再成功；带数字的 Claim 会逐项对照其实际引用 Evidence/Calculation，无法精确支持的数字降为 `insufficient`。
- 数值约束收紧后的提示词版本提升为 `r4-claims-v2`，新 Run 会持久化该版本，避免与旧提示词结果混淆。
- LLM 适配恢复冻结的 `generate(task_name, prompt_version, messages, response_schema, budget)` 端口，事件记录模型、token usage、耗时和 request_id；供应商响应未提供直接费用字段，费用仍需账单侧核对。
- 新增 11 项边界测试，覆盖反证越界、未提供证据、空输出、数字不支持、情景 Claim、冻结快照缺事实、中文检索、`top_k`、Fact revision、工具预算及供应商元数据。

上一轮漏检不是测试未执行，而是测试断言层级不足：Fake LLM 永远返回单条合法引用，工具测试只核对名称而未核对参数，情景测试只核对 Scenario/Calculation 数量，未检查最终 Claim；同时只测试了“缺情景参数可恢复”，没有用不可变快照验证“缺事实不可恢复”。审查还把“引用 ID 在整个快照存在”误当成“模型实际见过”，并以全量测试绿色替代了反证、空输出和真实供应商行为的针对性用例。本次已将这些漏检路径分别固化为回归测试。

## 真实 DeepSeek 三次验收

在临时数据库、公开 fixture 证据和环境注入密钥上执行三次最终端到端调用，供应商返回模型 ID `deepseek-flash`；三次 Run 均为 `completed`，均返回 usage、latency 和 request_id，耗时分别为 2234/1750/1500 ms，且没有非法引用导致的 `rejected` Claim。第三次同时生成 1 个 Scenario 和对应确定性情景 Claim。模型 Claim 中不能被引用对象精确支持的数字按设计降为 `insufficient`，未伪装为已支持。

## 尚未完成且不得宣称完成

- DeepSeek 响应没有直接费用字段，实际费用仍需在供应商账单侧由团队核对；不得从 token usage 猜测费用。
- 可见浏览器版面和团队第二位开发者独立复现仍需实际人员完成。
- 报告生成、导出和PDF属于R5，本轮未实现。
