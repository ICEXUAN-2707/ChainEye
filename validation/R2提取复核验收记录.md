# R2 提取与复核后端验收记录

日期：2026-10-01。分支：`feat/r2-extraction-review-backend`。基线：`feat/r2-upload-backend`提交`d3db285`。本记录覆盖B（确定性提取与证据）和C（人工复核事务）的统一后端实现，不代表前端分支已合并，也不代表R3及以后能力完成。

## 实现范围

- 上传成功后同步调用`Parser.parse(source_id, bytes) -> DocumentPages`，保存每页文本、词/块坐标、表格候选和解析警告；不启用OCR、LLM或任意代码执行。
- 只支持规格冻结的宁德时代2024/2025文本层年报版式。候选识别同时检查公司与报告年份、目标表标题、行名、年份列、千元单位和合并/分产品上下文。
- 生成15个年度候选字段：集团9项，动力电池3项，储能电池3项；金额从千元精确转换为人民币元，披露毛利率从百分数精确转换为ratio。
- Evidence使用真实Source、SHA256、PDF页码和数值词bbox。无法唯一识别时写`missing + null + missing_reason`；不同来源同口径但值不同新增`conflict`候选，不覆盖旧事实；自动流程不写`verified`。
- `PATCH /api/v1/facts/{id}`启用既有FactCorrection契约。事务内再次比较`expected_revision`、校验证据属于当前数据包版本，并原子写入Fact新revision、Dataset新版本和`fact_corrections`日志。旧快照保持可读。
- `raw_value`省略时按当前Fact原单位反算；金额除1000，ratio乘100。请求提供的原值与规范值不一致时返回422；revision冲突返回409 `REVISION_CONFLICT`。

## 契约交叉自检

- API操作数和请求/响应静态形状未增加；仍使用`SourceAttachment`、`FactCorrection`和`Fact`，没有并行DTO。
- OpenAPI仅更新当前能力描述；`frontend/src/api/generated.ts`无差异。
- Dataset/Fact不可变语义、十进制字符串、`null + missing_reason`、证据范围及模型不得写`verified`均有代码与测试约束。
- Scenario、Run、Agent、DeepSeek、报告和公网认证未实现，既有入口继续明确返回501；未修改前端组件或业务实现。

## 限制与待办

- 提取器不是通用财报解析器，只接受当前冻结的公司、年份和版式；扫描件及版式不符材料进入`needs_review`。
- 当前上传请求同步解析整份PDF；未实现R4任务队列、重试或后台编排。
- 未进行OCR、表格机器学习、语义检索、模型调用、情景计算或报告生成。
- 前端B+C页面仍需在其分支可集成后，按现有契约完成联调；本分支没有越界修改前端组件。
- 第二位开发者独立复现、双方互审和团队财务签核尚未执行，不能由本记录代签。
