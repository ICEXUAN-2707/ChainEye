# 链眼 · 使用手册

链眼是一个「面向产业链的可溯源投研智能体」：在受控数据环境中，把年报研究从「数据提取 → 人工复核 → 财务诊断 → 情景研究 → 智能研究 → 报告」走成一条保留数据版本、计算输入和引用对象的闭环。首版受控案例为宁德时代 2024/2025 年报，重点展示动力电池与储能业务；当前不宣称支持任意公司或任意版式的年报自动提取。

## 一、快速启动

环境要求为 Python 3.12、Node.js 22 或 24。进入仓库根目录，先创建 Python 虚拟环境并安装锁定依赖。

Linux/macOS：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.lock
python tools/start_backend.py
```

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.lock
python tools/start_backend.py
```

后端启动后，另开一个终端启动前端：

```bash
cd frontend
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。后端在 `http://127.0.0.1:8000`，接口文档 `/docs`。

**DeepSeek 密钥**仅用于「研究任务」的实时智能生成。推荐在仓库根目录创建不提交的 `.env`：

```dotenv
DEEPSEEK_API_KEY=<your-key>
DEEPSEEK_MODEL=deepseek-flash
# 可选：需要固定 PDF 字体时填写本机 CJK TTF/TTC/OTF 文件路径
CHAIN_EYE_CJK_FONT_FILE=
```

`tools/start_backend.py` 会加载该文件，但不会覆盖启动进程中已存在的同名变量。Windows PowerShell 也可在当前会话使用 `$env:DEEPSEEK_API_KEY="<your-key>"`；`setx` 只对之后新开的终端生效。未配置密钥时，研究任务会明确记录 `MODEL_UNAVAILABLE`，不会生成成功报告；数据复核、财务诊断和情景计算不依赖模型密钥。PDF 导出会优先使用 `CHAIN_EYE_CJK_FONT_FILE`，否则发现常见系统 CJK 字体并嵌入子集；显式路径无效时启动后的 PDF 请求会明确失败，未发现系统字体时回退 PyMuPDF 内置 CJK 字体。

当前服务仅允许本机访问，不得把本地模式直接暴露到公网。

## 二、使用流程（四个标签页）

### 1. 数据复核 —— 建立可信基线

- 上传年报 PDF（≤30 MiB、≤500 页、非加密文本型）。当前确定性候选提取仅支持宁德时代 2024/2025 年报的受控表头、行名、年份列和单位上下文；其他公司、年份或版式会进入 `needs_review`，不能当作自动提取成功。
- 表格展示「原值 / 规范值 / 单位 / 期间 / 业务 / 状态」，缺失与冲突用彩色徽标区分。
- 点击任意一行进入「人工复核」，左侧改值、右侧同屏显示原文证据（PDF 页码 + 摘录 + 坐标 + SHA256），确认后才标记「已复核」。

### 2. 财务诊断 —— 2024 vs 2025 对比

- 切换集团 / 动力 / 储能，看经营指标（收入、成本、毛利率、归母净利润、现金流）与资产负债指标（存货、应收、资产）的两年对比。
- 底部「核查提示」明确：存货/应收增长是核查信号、非结论；扣非差额 ≠ 非经常性损益。

### 3. 情景研究 —— 条件情景计算

- 选择业务与基线年度，设置三个研究假设：成本暴露 s、价格冲击 x、客户传导 k，确认后运行。
- 展示基线 vs 情景的「收入 / 成本 / 毛利润 / 毛利率 + 变化」，并可展开计算溯源。
- 「27 格点敏感性」一键跑 s×x×k 组合，用热力表看毛利率随假设变化的敏感性。

### 4. 研究任务 —— 智能体闭环

- 输入一条研究问题（如「分析 2025 年动力电池业务收入和毛利变化」），选择业务与模式，创建任务。
- 后端自动编排：数据提取 → 基线校验 → 财务计算 → 受控模型调用 → 引用核验 → 报告生成。
- 页面实时展示状态、事件时间线以及通过引用存在性和数字对照检查的 Claim（事实/计算/推论，带引用数），完成后可导出 Markdown / PDF 报告。`pending` Claim 的关键支持性仍需人工复核，不能等同于团队签核。

## 三、演示脚本（5 分钟）

1. **开场**（30s）：一句话定位——「链眼把一份年报变成一条可追溯的投研闭环」。
2. **数据复核**（1min）：上传受支持的宁德时代 2025 年报 → 展示 15 条候选事实 → 复核一条「收入」并点开原文证据，强调该数值绑定 PDF 页码、坐标和文件哈希。
3. **财务诊断**（30s）：切到「财务诊断」，看 2024 vs 2025 收入/毛利率对比。
4. **情景研究**（1min）：设 s=1、x=-0.1、k=0.5 运行情景，展示毛利率变化；再跑 27 格点敏感性。
5. **研究任务**（1.5min）：输入研究问题 → 展示智能体自动编排的节点流转 → 生成 1–3 条带引用的 Claim → 说明 `pending` 人工复核边界 → 导出 Markdown 报告。
6. **收尾**（30s）：强调「事实-计算-推论三层分离 + 全链路溯源 + 可复现」三个竞赛核心点。

## 四、可追溯与可复现

- **可追溯**：报告保存 Fact revision、Calculation 输入、Assumption、Evidence 与限制；数值 Claim 必须通过所引用对象的数字对照，SHA256 用于校验原始文件。`pending` Claim 仍保留人工支持性复核要求。
- **确定性计算**：相同 Fact revision、公式版本与假设产生相同财务/情景计算；报告绑定数据快照版本，不随后续事实修改而静默变化。
- **模型与回放边界**：实时 DeepSeek 输出不承诺逐字一致。回放复用已保存的源 Run 产物且不调用模型，但必须在界面和演示中明确标识为回放。

正式演示前应准备一次已人工检查的实时 Run 及其同快照回放 ID。网络或供应商异常时可以展示回放，不得把回放描述为当场实时调用成功。
