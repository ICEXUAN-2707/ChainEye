# 分轮开发任务与验收

## 最终交付物
D1 可运行Web工作台：数据包、复核、财务分析、假设情景、证据与报告。
D2 与现场版本一致的源码、Prompt、工具定义、模型配置模板、依赖锁文件、Docker Compose、运行说明。
D3 数据包：原始材料、来源和哈希、标注样本、未见样本、价格状态和限制；与公开提交相关的许可/来源说明。
D4 报告：Markdown、JSON、PDF；事实、假设、公式、支持证据、反证与风险边界。
D5 评测包：字段提取、计算、引用支持、稳定性、泛化、性能/费用、单次提示基线对照。
D6 上线交付：本地一键运行，团队演示服务器部署记录、访问保护、备份恢复说明。
D7 参赛材料：初赛计划书PDF和≤5分钟≤500MB视频；决赛报告、演示脚本、现场实时样例、备用回放。以赛事后续通知为准。

## 每轮统一执行要求
1. 开始前读取README、PRD、Spec、接口和上一轮验收报告。每轮只实现该轮范围。
2. 先列文件范围、接口变更和风险，再实现。不得让AI另建一套DTO或计算公式。
3. 完成一个纵向可运行流程后再扩展，避免两个开发者各做不可集成的大模块。
4. 验收报告写清新增行为、运行命令、测试结果、实测限制、下一轮阻塞项。截图不能替代数值和契约测试。
5. 必须由另一开发者运行至少一个关键流程，确认输入到输出及证据链。未通过项修复后再推进。
6. 接口变更需更新OpenAPI/Schema/前端类型/测试/变更记录，涉及语义或字段破坏性变化升级版本。
7. 财务字段不能因为某个模型提取困难就删去口径；数据缺失降低能力并说明，不能造数据通过验收。

## 核心验收案例
T01 两业务基线毛利率重算与披露差<=0.005个百分点。
T02 零冲击/零暴露回到基线；全传导保持毛利润且毛利率可变化。
T03 不同业务、年度、单位、范围组合拒绝；未复核和缺失基线拒绝。
T04 模型输出数字无计算/事实引用即拒绝；不存在的source或claim引用拒绝。
T05 单日期价格不得计算月均，spot与index混合拒绝；期货无合约和换月规则拒绝。
T06 修改事实产生新revision；旧Run仍可查看原快照；新结果必须重算。
T07 原件哈希改变时禁止把旧bbox和事实当成新证据。
T08 工具故障、模型超时、预算耗尽，Run保存partial/failed，不显示成功。
T09 同数据同Idempotency-Key相同请求复用，不同请求409。
T10 两用户相互访问dataset/run/source/report被拒绝；文件名路径穿越被拒绝。
