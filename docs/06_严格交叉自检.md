# 严格交叉自检 v0.2

本轮对原始PDF、金标准、PRD、Spec、领域模型、JSON Schema和HTTP契约交叉核查，并实现R1基础骨架。本轮是同一助手的再次原文复核与程序检查，不是第二位金融专家或独立开发者签核。

## 原文标注核查
两份原件SHA256与manifest一致。30条标注逐项复查原文行名、年份列、单位和规范值；未发现数值或口径错误。2024第9/20/114/119页及2025第11/25/111/116页覆盖所有关键字段；原文截图/文本辅助复核。金额由千元乘1000，披露毛利率由百分数除100。
2024净利润是归母；经营现金流是集团合并；两者辅助比值保留口径差异。库存是期末余额，非全年费用。集团营业成本不是营业总成本。分业务收入和成本不使用集团电池销量作为分母。
核查事实未改变。当前verified是R0助手复核样本状态；真实上传流程必须经过人工复核，不赋予LLM写verified的权限。团队签核仍待完成。
价格仍只有2025-12-31一个日期，两个报价属于不同series；未升级历史能力。

## 契约变更与兼容性
v0.2不是直接替换v0.1的兼容补丁：新增必填版本、收紧金额字符串、改变情景结果和上传响应。两名开发者必须同时切换，禁止混用旧客户端。
核心API16个操作，另有health；API模式和实现状态以生成规范及R1验收记录为准。
Schema描述静态形状，业务关联/权限/版本/引用语义仍必须由application层校验；不能用“类型检查通过”代表业务验证完成。

## R1实际范围
已实现：SQLite迁移、持久化空数据包创建、版本读取、样本seed、事实筛选、证据/来源查看、原始PDF文件服务、统一错误、OpenAPI导出、TypeScript类型生成、React样本工作台。
未实现：上传处理、事实更正、情景HTTP服务、任务编排、DeepSeek、报告及公网认证。相应写接口显式501，不生成假成功。
纯情景计算内核仍可独立测试，不等于HTTP业务服务完成。

## 开发前门槛
后端和前端各自按tasks任务单复现；团队签核样本；若修改契约，重新导出并运行契约漂移测试。R1不宣称自动提取系统准确率，也不宣称LLM或历史价格已经通过。
