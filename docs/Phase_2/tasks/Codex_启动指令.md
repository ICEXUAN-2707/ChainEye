# 给Codex CLI的启动指令

你接手链眼第二阶段。用户要求在现有demo基础上支持多电池企业、扫描PDF与新能源深度研究。两名开发者：你负责架构/核心后端/集成，Claude负责前端。
先读取仓库AGENTS/README、`docs/Phase_2/`全部文档以及当前代码/迁移/契约/测试。不要把旧R1测试结果当当前结果，不重建或覆盖现有仓库，不处理无关未提交改动。

第一轮执行：
1. 记录当前分支、commit、未提交状态和远程；核查现有上传、复核、场景、Run、模型与报告，按implemented/partial/stub/missing逐项举证。
2. 在既有协作规则上建立main稳定/develop集成/feat任务/release验收映射，发现等价分支复用。没有明确远程或授权不擅自推送、合并稳定分支。
3. 检索本包列出的GitHub及官方文档，读实际模块和许可证，固定commit；至少两个OCR候选做相同样本POC，记录安装、字段准确率、内存与耗时。
4. 获取第二家电池企业官方财报，保存来源/发布日期/hash；建立适配与未见测试分离，不能抄固定答案。
5. 完成current-state、repo-research、ADR、contract-delta、数据集/预算及验收计划；将本包语义增量落实到现有生成链。不能另手写一份OpenAPI作为权威。
6. 原流程回归通过后，交付P2.0核查与选型结果，然后在任务分支实施P2.1企业及P2.2解析第一纵向流程。按块提交可审查PR，不一次性重写全系统。

若未选择出可用OCR，保持needs_review降级并保存失败结果，继续不依赖选型的企业/契约工作。涉及改变金融含义/首版范围时列具体方案由团队决策。
后续按P2.3五模块研究、条件性建议、P2.4完整集成推进；所有数字来自程序与真实证据。保存真实运行结果和未完成项，不伪造通过。
每次报告：新增行为、关键文件、契约/迁移变化、检查命令与结果、限制、Claude联调步骤及下一块任务。
