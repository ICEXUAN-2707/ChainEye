# 契约与数据协议（设计增量）

## 权威与兼容
本文件是语义提案，不是现有仓库生成OpenAPI。Codex先建立contract-delta映射；能复用的Dataset/Fact/Evidence/Run/Calculation/Claim/Report保持复用，不并存第二套DTO。
从实际后端模型/路由生成OpenAPI/Schema/前端类型，生成检查进CI。移除CATL硬编码Literal时升级模型并测试旧fixture兼容。不能把旧domain segment简单改成任意字符串；采用受控segment_code并保留原披露名称。
新增必填/枚举/状态改变是破坏性变更，迁移、客户端同时升级；旧Run与旧报告继续读取原快照。

## 实体最小字段
|对象|字段及约束|
|---|---|
|CompanyProfile|id、legal_name、aliases、security_ids、industry_profile_id、profile_version；证券代码不作全球唯一ID|
|DatasetIdentity|dataset_id、expected_version、company_id、report_year、report_type、confirmed、confirmation_reason；由人确认，公司或年度更正新版本并使旧分析stale|
|IdentityCandidate|company候选/年度/类型、evidence_ids、warnings；未确认不归属事实；未知企业可新建人工档案|
|ParseJob|id、source_id、source_sha256、dataset_id、base_version、engine/model/config版本、status、processed_pages/total_pages、warnings/error；无绝对路径和密钥|
|PageArtifact|source_id、hash、page_no(1-based)、method、text、blocks、tables、width/height/rotation/cropbox、pixel_to_pdf_matrix、warnings；可单独分页读取|
|TableCell|row/col及span、text、bbox、source_page、header关系；保留跨页来源|
|Fact增量|company_id、segment_code、reported_segment_name、extraction_method、artifact_id；保留原值/规范值/证据/revision及所有原金融约束|
|CapabilityItem|module_id、status、reason_code、required_inputs、missing_inputs、evidence_gaps、supported_actions；ready/needs_review/missing_data/unsupported/failed|
|ResearchFinding|id、module_id、claim_ids、fact_ids、calculation_ids、alternative_explanations、counter_evidence_ids、limitations、support_status；supported/partial/insufficient|
|Recommendation|id、finding_ids、audience、action、rationale_claim_ids、conditions、tracking_metric_ids、trigger_rules、limitations；没有依据不得输出确定建议|

所有对象通过ID关联；输入Fact revision集合与计算一致。Report需嵌入完整能力声明、事实/计算/假设及建议快照，不能只引用会改变的latest对象。行业/企业配置、Prompt、模型和解析配置版本保存在Run。
时间ISO8601含时区，业务日期ISO日期；金额/参数/分数十进制字符串；未知值null+reason。OCR confidence是引擎评分，保存范围/含义，不承诺概率校准。缺坐标允许null；强证据必须真实页/哈希。

## 路由增量建议（沿用/api/v1）
|动作|请求|响应/语义|
|---|---|---|
|GET /companies|offset/limit|CompanyCollection；仅展示已建档企业，不等于分析全支持|
|POST /companies|名称/可选证券标识/行业profile|201 Company；人工建档并去重校验|
|GET /datasets/{id}/identity-candidates|version必填|候选及证据，未识别有明确原因|
|POST /datasets/{id}/identity-confirmations|DatasetIdentity|新版Dataset；expected_version冲突409|
|POST /sources/{id}/parse-jobs|dataset_id/base_version、engine_profile、page_range可选、Idempotency-Key|202 ParseJob；检查来源归属与范围|
|GET /parse-jobs/{id}|无|ParseJob状态|
|GET /parse-jobs/{id}/pages|offset/limit|页结果集合；不返回整本巨大文本|
|GET /datasets/{id}/capabilities|version、industry_profile_version|CapabilityCollection；用事实/模型条件判定|

现有上传SourceAttachment、facts(version必填)、PATCH(expected_revision/reason)、runs/events/report优先复用。若已有解析作业路由，用映射替代新增路由；无需为了符合名称重建接口。研究模块/建议作为现有Run/Report扩展，不默认新增research-run。
确认公司后，可复用已完成的页解析；确认前只生成无归属候选材料。重新归属必须产生新版，不静默修改已引用Fact的公司。
错误统一error、code、message、details、retryable、request_id。新增错误建议IDENTITY_UNCONFIRMED/IDENTITY_CONFLICT/OCR_UNAVAILABLE/PARSE_PARTIAL/UNSUPPORTED_MODEL/MISSING_INPUT/STALE_SNAPSHOT；普通缺口通过capability和partial表达，不全都抛500。

## 数据库迁移
新增company/profile、parse_job/page_artifact、identity_confirmation记录与必要关联；事实字段扩展采用新增迁移。禁止覆盖已运行迁移。事实归属、版本发布、revision更正须事务；备份后验证旧数据、旧报告和索引兼容。大页内容用受控文件或表保存，接口仅ID映射。
